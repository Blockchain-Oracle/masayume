## 2. Findings

### F-1 — Vercel AI SDK "v6" is a stale major; current is v7 `[CORRECTION REQUIRED]`

The Stack table commits to `ai` **v6**, but AI SDK **7.0.0 shipped 2026-06-25** and `ai@latest` is now 7.0.87. A fresh `pnpm add ai` installs v7, so the spine as written will not match what a builder gets by default. Compounding it: the AI Gateway documentation for the spine's own default model (`anthropic/claude-opus-5`, reasoning-effort control) is written against v7's top-level `reasoning` option. v6 still receives patches (npm `ai-v6` dist-tag → 6.0.273) and official codemods exist for 6→7.

**Correction:** change the Stack row to **AI SDK v7** (requires Node 22+, `@ai-sdk/*` bumped together, `@ai-sdk/otel` if tracing). If v6 is instead deliberately retained, the spine must say so and pin via the `ai-v6` dist-tag — but there is no stated reason to, and Baku's server-side LLM usage (`generateText`/`streamText` + gateway model string) migrates near-mechanically.

### F-2 — wagmi "v2 line" is correct, but only because RainbowKit forces it — record the reason `[CORRECTION REQUIRED — one line]`

wagmi's current major is **v3** (3.7.7; v3.0.0 released 2025-11-19). The spine's "wagmi v2 line + current RainbowKit" happens to be the *only* compatible pairing — RainbowKit 2.2.11 (latest, 2026-05-06) peer-requires `wagmi ^2.9.0`, and wagmi-v3 support is still an open RainbowKit discussion (#2575) — but the spine presents v2 as if it were simply current. It is not: **the last wagmi 2.x publish was 2.19.5 on 2025-11-19**, i.e. the v2 line has been frozen for ~9.5 months.

**Correction:** annotate the Stack row: "wagmi v2 (pinned by RainbowKit peer `^2.9.0`; wagmi v3 not yet supported by RainbowKit — revisit only if wallet-connect bugs surface)." Residual risk to accept knowingly: a frozen wagmi 2.19.5 under Next 16.3/React 19.2 is a combination the wagmi team no longer ships fixes for; peer ranges are satisfied (`react >=18`, `viem 2.x`, TSQ `>=5`) and RainbowKit 2.2.11 was released well into the React 19 era, so this is acceptable for the hackathon — but if RainbowKit misbehaves under Next 16, the fallback is wagmi v3 + a different connect kit, not waiting for a wagmi 2.x patch.

### F-3 — Railway "free" is a 30-day trial credit, not a free tier `[NOTE]`

Viable for this build: $5 one-time trial credit, no card, 30 days — covers a single ops service through the 8 Sep 2026 deadline. But anything meant to stay up for judges *after* the trial window (or if the account's trial was already consumed) needs Hobby at $5/mo; the post-trial "Free" plan ($1/mo credit) will not keep an always-on Node service alive. No architecture change — just don't describe Railway as free in ops docs, and check the account's trial status before demo week.

### F-4 — Drizzle/Neon: compatible now, but only above a known cliff `[NOTE]`

`@neondatabase/serverless` 1.x broke `drizzle-orm/neon-http` at 1.0.0 (drizzle-team #5208); fixed in drizzle-orm 0.40.1+. Current latest (drizzle 0.45.2 + driver 1.1.0) are compatible. When `packages/db` is created, pin `drizzle-orm >= 0.40.1` so a resolution accident can't resurrect the bug.

### F-5 — Everything else verified clean `[NO ACTION]`

markets-sdk 0.28.1 (exact-pin justified — nine releases in 17 days of August shows the "indexer schema drift is real" note is earned), Next 16.3.4/React 19.2.8 (both npm `latest`, mutually compatible, scaffold proven by `next dev`-generated AGENTS.md), Tailwind 4.3.3, shadcn/ui React 19 + Tailwind v4 + `@theme` (AD-12 sound), TanStack Query 5.102.8 (no v6 exists), viem 2.56.1 consistent across all peers, grammY 1.46.0 (active, long-polling documented as the recommended single-process mode — AD-8 fit confirmed), Foundry stable v1.8.1, Neon free plan generous post-acquisition, and the `anthropic/claude-opus-5` gateway model string is real and live (AI Gateway, since 2026-07-24).
